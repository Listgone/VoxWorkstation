# VoxWorkstation

> 把小说 / 剧本变成配音成品的桌面工作站 —— 文本处理 → 配音 → 导出，全流程在一个软件里完成。

Electron 桌面端 + [VoxCPM2](https://github.com/OpenBMB/VoxCPM) 语音合成引擎。不依赖任何在线服务即可完成配音；接入大模型后还能自动把原文整理成带角色与情绪的规范剧本。

## 它能做什么

| 环节 | 说明 |
|---|---|
| **项目化管理** | 项目 → 季（区间划分）→ 集。集数可以很多，文件夹平铺，不建季子目录 |
| **文本处理** | 粘贴原文 → 一键整理成 `【背景介绍】+【角色（情绪）+台词】`；本地规范化不联网 |
| **配音** | 按角色绑定音色，逐句生成；每句生成完立即落盘，中途关软件不丢进度 |
| **导出** | 整轨合并、SRT 字幕、逐句目录；导出记录留档 |
| **音色库** | 声纹克隆 / 音色设计 / 高保真，先试听再保存 |
| **四种主题** | 明亮现代 / 极简黑白 / 液态玻璃 / 构成主义 |

## 环境要求

| | 要求 |
|---|---|
| **系统** | Windows 10 / 11（x64） |
| **显卡** | NVIDIA，建议 8GB+ 显存（VoxCPM2 依赖 CUDA） |
| **Python** | 3.10+，需在 PATH 中 |
| **VoxCPM2 后端** | 默认在项目内的 `engine\` 目录（含 `server.py` 与 `pretrained_models\VoxCPM2`，约 4.7 GB） |
| **磁盘** | 模型约 5–10 GB，音频输出按需 |

> 首次启动需要加载模型，约 **30 秒到 3 分钟**（取决于磁盘与显存）。
> 界面**不会**被阻塞 —— 服务一响应就能进主界面，可以先去整理文本，模型在后台继续加载。

## 安装

### 方式一：安装包（推荐）

下载 `Releases` 里的 `VoxWorkstation Setup x.y.z.exe`，双击安装。

安装后还需准备 VoxCPM2 后端（见下方「后端配置」）。

### 方式二：从源码

```bash
git clone <本仓库地址>
cd VoxWorkstation
npm install
npm start
```

### 后端配置

软件通过 `vox.config.json` 找到后端：

```json
{
  "serverPort": 8000,
  "serverDir": "D:\\VoxWorkstation\\engine",
  "pythonPath": "python",
  "autoStartServer": true
}
```

| 字段 | 说明 |
|---|---|
| `serverDir` | VoxCPM2 所在目录（须含 `server.py`） |
| `pythonPath` | Python 可执行文件；不在 PATH 中就写完整路径 |
| `serverPort` | 后端端口，被占用时改这里 |
| `autoStartServer` | 是否随软件自动拉起后端 |

也可以用环境变量覆盖：`VOX_SERVER_DIR` / `VOX_PYTHON`。

## 快速上手

```
① 建项目  →  ② 建集  →  ③ 文本处理  →  ④ 配音  →  ⑤ 导出
```

1. **项目管理** → 新建项目（一个项目 = 一部作品）
2. **集管理** → 新建集，会创建 `第01集` 文件夹
3. **文本处理** → 粘贴原文 → 「作为原文」→ 点 **✦ 整理成剧本**
4. 核对分句表的角色与情绪，不对就改
5. **配音** → 给角色绑定音色 → 「生成全部」
6. **导出** → 整轨合并 / 生成 SRT

## 核心概念

### 项目 → 季 → 集

- **项目**：一部作品，对应一个文件夹
- **季**：**只是集号的区间划分**（如「第一季 = 第 1–20 集」），用于分组显示。
  季不建子文件夹，集始终平铺在项目目录下，改区间不会移动或删除任何文件
- **集**：最小工作单元，一集一个文件夹

### 分句与状态

每集包含若干「台词行」，每行有角色、情绪、音色、音频文件。

- **角色名与情绪只是标注，不参与配音** —— 送进 TTS 的只有台词本身
- 情绪分三级：**原文明确**（`愤怒`）/ **推断**（`推断：无奈`，仅作参考）/ **未标明**（按中性处理）
- 集状态：草稿 → 文本处理中 → 配音中 → 已完成 → 已交付

## 文本处理详解

### 两种处理方式

| | 说明 | 需要联网 |
|---|---|---|
| **✦ 整理成剧本** | **一键完成全流程**：规范化 + 断句 + 角色识别 + 情绪标注 + 背景介绍 | 需要 AI |
| **本地规范化** | 数字 / 日期 / 金额 / 单位 / 缩写 → 口语读法 | 不需要 |
| **按角色 / 标点分句** | 按标点和 `角色：台词` 前缀切句 | 不需要 |
| **✦ AI 处理…** | 分步执行，只做其中某一环时用 | 需要 AI |

> **只想要剧本，点「✦ 整理成剧本」一个按钮就够了。**

### 输出的剧本格式

```
【背景介绍（仅供判断，不配音）】
深夜的电台直播间，窗外落着雨。主持人小明与嘉宾老周聊起十年前的往事。

【角色（情绪）+台词（用于配音）】
小明（平和）+大家好，欢迎收听今晚的节目。
老周（推断：无奈）+那一年，我差点就关门了。
黑衣人（未标明）+东西我拿走了。
```

- `【背景介绍】`**不配音**，只供你判断上下文
- 只有**明确说出口的台词**进配音；旁白、动作、环境、心理描写全部归入背景介绍
- 无名角色用稳定代称（如「黑衣人」）

### 本地规范化覆盖范围

数字读法是确定性规则，本地做比 AI 更稳定。已覆盖：

| 类型 | 示例 |
|---|---|
| 年份 / 日期 | `2024年3月5日` → 二零二四年三月五日 |
| 百分比 / 千分号 | `3.14%` → 百分之三点一四 |
| 金额 | `￥1,234.56` → 一千二百三十四元五角六分 |
| 温度 | `25℃` → 二十五摄氏度 |
| 时间 | `15:30` → 十五点三十分 |
| 分数 / 比例 | `1/2` → 二分之一；`3:1` → 三比一 |
| 范围 | `3-5km` → 三到五公里 |
| 数学符号 | `A+B=C` → A加B等于C；`x≥5` → x大于等于五 |
| 单位 | 17 种，含 `km/h`、`kWh`、`GB`、`㎡` |
| 缩写 | `GDP` → G D P（全大写 2–6 字母逐字母） |
| 长数字 | 电话、编号逐位读 |
| 负数 / 序数 | `-15%` → 负百分之十五；`第12集` → 第十二集 |

## AI 服务配置

**设置 → AI 服务**。支持 4 家 + 自定义：

| 服务商 | 说明 |
|---|---|
| **DeepSeek** | 国内直连，**推荐**。`deepseek-flash` 便宜且快 |
| **智谱 GLM** | 有免费模型（`glm-5.3-flash`） |
| **OpenAI** | 需要能访问境外 |
| **本地 Ollama** | 本地部署，数据不出网，**不需要 API Key** |
| 自定义 | 任意 OpenAI 兼容端点 |

### 操作步骤

1. 选一个服务商（地址与模型会自动填好）
2. 粘贴 **API Key**
3. 点 **「测试连接」** —— 会先自动保存 Key 再测试
4. 点 **「⟳ 拉取」** 获取该服务商**真实可用**的模型列表

> **每个服务商的 Key 分开保存**，切换时自动带出各自的，不会互相覆盖。
> Key 用系统凭据加密存储，界面只显示掩码（如 `sk-••••••1234`）。

### ⚠️ 深度思考务必保持关闭

DeepSeek 的思考模式**默认开启且强度为 high**，模型会先写一大段思维链再作答 ——
200 字的整理任务会因此耗时 **60 秒以上**。关闭后**不到 2 秒**。

设置 → AI 服务 → **深度思考 → 关闭（快）**（该项只在 DeepSeek 下显示）

## 本地模型（Ollama）

不需要 API Key，也不需要本软件管理模型文件。

```bash
# 1. 安装 Ollama（ollama.com），装完它会在后台常驻
# 2. 拉一个模型
ollama pull qwen2.5:14b
# 3. 回到软件：设置 → AI 服务 → 本地 Ollama → ⟳ 拉取 → 选一个
```

- 模型存在 Ollama 自己的目录（默认 `%USERPROFILE%\.ollama\models`）
- 本软件只通过 `http://127.0.0.1:11434` 调用，**不复制模型文件、不改动 Ollama 目录**
- **模型建议**：剧本整理是结构化长输出任务，`qwen2.5:14b` 起步；
  显存紧张退到 `7b`，但人名与角色识别会明显变差

## 文件都存哪

```
<输出根目录>\
  .trash\                    删除的项目（保留 30 天，可恢复）
  <项目名>\
    project.voxproj          季划分 / 角色音色 / 词典
    _shared\
      dict.json              项目词典
      voices\                声纹文件
    .trash\                  删除的集
    第01集\
      script.original.txt    原文（只读，保证可回溯）
      script.txt             处理后的台词
      lines.json             分句 + 角色 + 情绪 + 状态
      episode.json           集元数据
      audio\                 逐句音频
      output\                导出的成品
      export-log.json        导出记录
```

音频命名形如 **`001_旁白_这是第2集的.wav`** —— 序号 + 角色 + 台词前几字，方便辨认。

删除的项目 / 集进 `.trash`，**不会直接抹除**；超过保留天数（默认 30 天）在启动时自动清理。

## 自检与排错

**设置 → 诊断与关于 → 开始自检**，逐项检查并给出修复办法：

- 后端服务 / 语音引擎 / 后端脚本 / Python
- 输出目录可写性 / 磁盘空间
- AI 服务配置 / 本地 Ollama 连通性
- 配置目录权限

### 常见问题

| 现象 | 处理 |
|---|---|
| 界面停在加载页 | 模型在后台加载，服务一响应就进主界面。超过 5 分钟无变化 → 跑自检 |
| AI 很慢 | 关掉 DeepSeek 的「深度思考」 |
| 生成音频听不了 | 确认标题栏引擎徽章是绿色「引擎就绪」；加载中生成的请求会返回 503 |
| 换服务商要重填 Key 吗 | 不用，每家分开保存 |
| 人名识别不出来 | 多为模型能力问题，换更强的模型 |
| 后端起不来 | 自检会指出是脚本路径还是 Python 的问题 |
| **上传 m4a / flac 参考音频后生成失败或静音** | Windows 上 `soundfile` / `librosa` 解码 m4a(AAC) 不稳定，报 `LibsndfileError: Format not recognised`。后端已用 ffmpeg 自动转 16kHz 单声道 WAV，**前提是 ffmpeg 在 PATH 中** —— 未安装时会在控制台打 `[warn] ffmpeg 转码失败`，此时请手动把参考音频转成 WAV 再上传 |

## 开发

```bash
npm start                 # 开发模式运行
npm run build:win         # 打包 NSIS 安装包（输出到 dist/）
```

### 技术栈

- **Electron 31** —— 无边框窗口，`contextIsolation` + `sandbox`，渲染进程无 Node 权限
- **原生 JS 渲染层** —— 无打包器，按 `util → api → store → components → pages → app` 顺序加载
- **FastAPI 后端** —— 独立进程，通过 HTTP 通信；模型后台线程加载，`/api/ready` 查询状态

### 目录结构

```
main.js               主进程：窗口、IPC、后端进程管理、AI 调用、自检
preload.js            contextBridge 白名单
project-store.js      项目 / 集 / 回收站的文件读写
renderer/
  index.html          外壳
  css/style.css       设计系统 + 四套主题
  js/
    store.js          全局状态
    api.js            TTS 后端客户端
    components/       modal / select / notify / player / gpu / shortcuts / toast
    pages/            9 个页面
```

### 架构演进（为什么是前后端分离）

最早用 **Gradio** 搭过一版 Web UI，功能跑通了，但卡在界面上：
Gradio 的 Tab 逻辑是封闭的，想通过 CSS/JS 实现「左侧树形导航联动右侧内容」，多次尝试都无法稳定做到。

为了模块化和可扩展性，改为 **FastAPI 后端 + 自主前端**：后端只管推理与文件，前端完全自控。
后来又把前端从纯网页换成了 Electron 桌面端 —— 这样才能直接读写本地项目目录、管理逐句音频文件。

### 设计原则

- **角色名与情绪只是标注，不参与配音** —— 只有台词进 TTS
- **每句生成完立即落盘** —— 中途关软件不丢进度
- **删除进回收站** —— 不直接抹除
- **AI 与本地处理严格分开** —— 界面上用颜色区分，避免误以为本地按钮也要联网

## 已知限制

- 仅支持 Windows（打包配置为 NSIS）
- 需要 NVIDIA 显卡；AMD / Intel 核显未测试
- 本地断句**无法做到 AI 的说话人归属准确度** —— 那需要语义理解，本地只能靠引号与「说」字句规则
- 发音词典目前是**项目级**的，同一术语在不同项目里要重复维护（全局词典待做）
- 批量导入 txt、跨集队列、时间轴预览尚未实现
