## 项目

VoxCPM2 配音工作站 —— 把小说 / 剧本变成配音成品的桌面工作站。
文本处理 → 配音 → 导出，全流程在一个软件内完成。

---

## 技术栈

| 层 | 技术 |
|---|---|
| 前端 | Electron 31.7.5，无边框窗口，`contextIsolation` + `sandbox`，渲染进程无 Node 权限 |
| 渲染层 | **原生 JS，无打包器**，按 `util → api → store → components → pages → app` 顺序加载 |
| 后端 | FastAPI 独立进程，HTTP 通信；模型后台线程加载，`/api/ready` 查询状态 |
| 引擎 | `voxcpm` 2.0.3 + torch 2.5.1+cu121 + CUDA 12.1 |
| 打包 | electron-builder 25.1.8 / NSIS，**无代码签名** |

## 关键文件

| 文件 | 作用 |
|---|---|
| `main.js`（约 1700 行） | 主进程：窗口、IPC、后端进程管理、AI 调用、诊断、一键配置 |

| `renderer/js/pages/text.js` | 文本处理、`TextTools.normalize` / `parseScript` |
| `renderer/js/pages/dub.js` | 配音、本次生成列表 |
| `renderer/css/style.css` | 设计系统 + 4 套主题 + 加载页动画 |

## 已修复（均在 v1.4.0 生效）

### 打包与部署

- `build.files` 手工枚举漏掉 `project-store.js` → 安装后主进程 `require` 失败并崩溃；
  改为通配 `["*.js","renderer/**/*","assets/**/*","vox.config.json"]`，
  并增加打包前 `require` 目标存在性校验
- **`bootstrap/server.py` 与 `engine/server.py` 手工维护两份**，前者停留在 v1.0.4 时期，
  导致后续所有后端修复未进入安装包。改为 `prebuild:win` 自动同步 + 一致性校验
  （**这是最严重的一次事故，v1.0.16 / v1.0.17 的修复全因此失效**）
- `serverDir` 支持相对路径（相对应用目录解析）

### 后端

- **端口**：`server.py` 端口参数化 + **绑定处重试**（上限 60 个），
  解决 Windows 端口排除段（Hyper-V / WSL / Docker 预留）导致的
  `[Errno 13]` / `code=3`
- **torch**：`--extra-index-url` 改为 `--index-url`，从 CUDA 源单独安装。
  前者只是「备用源」，pip 仍优先 PyPI，而 PyPI 上 Windows 的 torch 是 CPU-only 构建
- **m4a / flac**：新增 `ensure_wav()`，ffmpeg 转 16 kHz 单声道 PCM_16，接入 6 处
- **模型下载**：移入后台线程 + 直链下载（实测 16.4 MB/s），
  弃用偏慢的 `modelscope.snapshot_download`
- **设备选择**：`_gpu_precheck()` GPU 优先，不达标退 CPU（强制 float32）

### 界面

- 加载页波纹背景（色相 188→231→277，取自图标配色）+ 图标出场动画
  （弹性放大 / 高光扫过 / 光晕爆发 → 呼吸）
- 进度条 `_smoothTo()` 插值补间；新增 `engine-loading` 事件
- `#titlebar` 的 `z-index` 由 2 提到 1200 —— 原先被 `#loading-overlay`（1000）
  完全遮挡，加载卡住时只能 Alt+F4
- 日志空态隐藏、自动滚到底、失败态文案

### 诊断

- `vox:diag:export` → `vox-diagnostic.txt`
  内容：系统 / 运行环境 / 模型文件清单 / **端口排除段与 30 端口逐个试绑结果** /
  配置（Key 打码）/ 日志尾部
- **两个入口**：
  - **设置 → 诊断与关于 → 导出诊断报告**（始终可用）
  - 加载页失败面板（**仅后端起不来时显示**）
- `POST /api/selftest` 测试语音

| 测试机完整流程 | ✓ 下载、安装、一键配置、生成语音全部跑通 |

| 实测显存 | 加载后 6743 MB / 生成峰值 7075 MB（模型本体约 5.5 GB） |

### 硬件需求（实测）

- **显存下限 6 GB**，8 GB 及以上更宽裕
- **GPU 架构需 8.0+（RTX 30 系及以后）** —— 模型以 `bfloat16` 加载
- 不满足则自动退 CPU，需约 10 GB 可用内存
- 已知不适用：GTX 1050 Ti（Pascal 6.1 / 4 GB）

## 未解决 / 已知限制

1. **私有仓库导致分享链接 404** —— 要给别人下载需另建公开 Release 仓库或走网盘
2. **GTX 1050 Ti 只能 CPU 模式** —— 架构不支持 bf16 + 显存不足，硬件硬限制
3. **无代码签名** —— 首次运行有 SmartScreen 警告
4. 未实现：批量导入 txt、跨集队列、时间轴预览、**全局发音词典**（现为项目级）
5. 桌面图标刷新依赖 Windows 缓存（已清 15 个 `iconcache*.db` 并重启 Explorer）

## 风险点

- **`bootstrap/` 与 `engine/` 仍是两份文件** —— 已有构建校验，但机制上仍可能被绕过。
  **务必走 `npm run build:win`，不要直接用 `electron-builder`**
- **未在真正的陌生机器上走过完整安装** —— 测试机是用户的第二台机器，
  可能与「完全没有 Python / 模型」的环境不同
- **诊断导出依赖内存中的 `logBuffer`** —— 应用重启后日志清空
