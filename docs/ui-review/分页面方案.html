VoxCPM2 工作站 · 分页面设计

按你说的拆成独立页面：配音就是配音，文本处理就是文本处理。下面是 5 个页面 + 我的取舍说明。

一、为什么是这 5 个页面

页面划分的唯一标准是「这一页只干一件事」。整条链是 文本 → 配音 → 导出，加上两个不属于流程的东西：音色资产和配置。

页面唯一职责产出
文本处理把原始文本变成可以直接配音的台词干净分句
配音把台词变成音频音频片段

侧边栏按 工作流 / 资产 / 配置 三段分组 —— 让用户一眼看出"前三个是有顺序的，第四个是随时用的，最后一个是配置"。

二、五个页面

① 文本处理 —— 导入（5 种来源）· 原文⇄处理后对照 · AI 工具条 · 分句表。底部一个「保存并前往配音 →」把结果交出去
② 配音 —— 角色配声（旁白→温柔女声，小明→少年音）· 台词表带逐句状态 · 右栏试听/参数/队列/多版本对比
③ 导出 —— 本次成品（整轨/逐句/SRT/工程）· 导出选项 · 导出记录（能找回上次导出的东西）
④ 音色库 —— 波形缩略图 + 行内试听 + 「用于 旁白」标记（一眼看出哪个音色正被哪个角色用着）
⑤ 设置 —— AI 服务商 / 发音词典 / TTS 后端 / 外观 / 诊断，五个分组各管一摊

三、我替你做的几个决定

1. 「导出」单独成页，而不是塞在配音页里

你说要单一性，那导出就不该只是配音页的一个按钮。单独成页后它能承担三件事： 本次成品（四种产出）、导出选项（格式/停顿/字幕/存档）、 导出记录（昨天导的那版在哪，一键打开目录）。第三件是塞在弹层里做不到的。

页与页之间用「保存并前往配音 →」「前往导出 →」这种明确的交接按钮串起来， 而不是靠用户自己想去哪。

2. 「发音词典」放进设置，不单独成页

它本质是一份配置数据（词 → 读法），不是每天都编辑的东西。放在设置的独立分组里， 文本处理页点「多音字校正」时把新词条写进来，两边共用同一份数据。

3. 「新建音色」放进音色库页，不做独立页面

音色设计 / 可控克隆 / 极致克隆 是获得音色的三种手段， 结果都落到同一个音色库里。放在音色库页做弹层，比做成第三个平级页面更符合"单一性" —— 因为它的产出物归属音色库。顺带修掉现在"必须先存才能听"的问题：先试听，满意再保存。

4. 「音乐」从导航里拿掉 建议删除

后端 server.py 里至今没有任何音乐相关接口， 那个页面从第一天起按钮就是灰的。占一个一级入口会让整个导航不可信。 接上了再加回来，或者放到设置里当实验功能。

五、技术要点（没变）

AI 统一走 OpenAI 兼容接口。DeepSeek、通义千问、Kimi、智谱、本地 Ollama 都提供 /v1/chat/completions，只实现一个客户端，把 baseURL + model + key 做成设置项。换服务商不用改代码，断网切本地， 某家涨价换别家。
