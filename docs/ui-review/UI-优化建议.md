# VoxWorkstation UI 优化建议

> 这份文档基于**实际运行截图**（用 Electron 加载真实 `renderer/` + 打桩后端跑出来的，非纸面推演）。
> 截图存放在 `docs/ui-review/`，均为本次修复后的当前状态。
> 文中 `文件:行号` 指向当前代码，方便直接定位。

---

## 零、先说结论

整体骨架是好的：三栏布局清晰、深浅两套主题 token 完整、卡片/按钮体系一致，**不是需要推倒重来的程度**。

问题集中在三类：

| 类别 | 典型表现 | 影响 |
|---|---|---|
| **信息呈现失真** | 波形画成一整块实心蓝条、像进度条 | 用户怀疑"这音频是不是坏了" |
| **空间利用失衡** | 1280px 宽下内容只占顶部 30–60%，输入框横跨全屏 | 显得空旷、业余 |
| **语义/反馈缺失** | 「风格预设」里是音色名、禁用按钮不说原因、只读框长得像可编辑 | 用户不知道该点哪里、点了没反应 |

按「改动量 ÷ 收益」排序，下面的 **A–D 是性价比最高的四项**。

---

## A. 波形图必须重做 —— 目前它看起来像进度条 ⚠️ 最高优先级

![配音页](ui-review/dub-dark.png)

看截图「生成结果」区域：那是一整块**实心蓝色圆角矩形**。它其实是波形，但没人看得出来。

**根因**（`renderer/js/components/player.js` 的 `drawWaveform`）：
1. 振幅几乎占满整个画布高度 —— `barH = mx * (mid - 3) * 2`，`mx` 接近 1 时柱高就是 54px / 60px
2. 柱宽 1px 且**无间隙**，逐像素铺满 → 连成一片
3. 没有中线
4. **没有播放头**，播到哪儿完全看不出来

**建议改法**：

```js
// 1) 上下留白，别铺满
const barH = Math.max(2, mx * mid * 0.78 * 2);

// 2) 柱子留间隙：每 3px 画一根 2px 宽的柱子，圆角
for (let x = 0; x < w; x += 3) { /* ... */ }

// 3) 画中线（--border 色，1px）
ctx.fillStyle = borderColor;
ctx.fillRect(0, mid, w, 1);

// 4) 播放头：单独一层 canvas 或用 clip 分色
//    已播放 → var(--accent)；未播放 → var(--text-muted) + 40% 透明
```

播放头建议做成**独立的一层**（两层 canvas 叠放，或用 `ctx.clip()` 重绘），这样进度更新时不必整幅重画，60fps 也扛得住。

**空状态**：未加载音频时画一条灰色平线 + 居中提示「生成后在此试听」，而不是留一片空白。

## B. 播放器控制区排布松散，白占一整行

同上看截图下半部分：

```
┌──────────────────────────────────────┐
│  [ 波形 ]                             │
├──────────────────────────────────────┤
│  [▶]  ▬▬▬▬▬▬▬▬▬▬▬     0:00 / 0:08   │   ← 第二行
├──────────────────────────────────────┤
│  下载                                 │   ← 第三行只有它一个
└──────────────────────────────────────┘
```

**建议**：压成一行，用图标按钮代替文字按钮：

```
[▶] [────●──────────] 0:04 / 0:08   [🔁] [⬇]
```

- 「下载」从文字按钮改成 14px 图标按钮（`btn-icon` 已有样式），省掉一整行 ≈ 32px
- 补上播放器**自己**的音量控制 —— 现在音量只能去右侧面板拖，鼠标要横跨整个窗口，很反直觉
- 可考虑 ±5s 快退/快进

## C. 右侧参数面板与播放器脱节

「音量 / 语速 / 音调」在**右栏**，播放器在**左下角**。调一次音要来回看两处，而这三项本质是「试听时随手调」的参数。

**建议拆分**：

| 参数 | 归属 | 理由 |
|---|---|---|
| 音量 / 语速 / 音调 | 移到播放器旁（紧凑横排） | 试听时的即时操作 |
| 稳定性(cfg) / 质量(steps) | 留在右栏 | 生成前设定，与试听无关 |
| 音色信息 | 留在右栏 | 参考信息 |

顺带：这三项是**纯前端播放效果**（`playbackRate` / `detune` / `gain`），改了不会影响生成结果。需要在 UI 上说明，否则用户会以为调了"语速"模型就会说得慢——**实际不会**。

## D. 表单控件全宽拉伸 + select 字体不一致

![克隆源](ui-review/studio.png)
![设置](ui-review/settings.png)

1280px 宽下，「风格预设」下拉、所有输入框都横跨约 960px。三个具体问题：

1. **无最大宽度**：`style.css` 里 `input, select, textarea { width:100% }`，父级 `.card` 也没有约束
   ```css
   .card { max-width: 640px; }      /* 或 */
   input[type="text"], select { max-width: 420px; }
   ```
2. **select 的字比周围粗且大**：截图里「温柔女声」「Chirp v5」「暗色」明显比旁边的 label 更抢眼。`select` 没有继承统一字重，建议显式声明 `font-weight:400; font-size:13px;`
3. **只读框看不出只读**（`settings.png` 的「服务地址 / 后端目录 / Python」）：它们和可编辑框长得一模一样，用户会去点。建议：
   ```css
   input[readonly] { background:transparent; border-color:transparent;
                     color:var(--text-secondary); padding-left:0; }
   ```

## E. 「风格预设」的语义是错位的（功能 + UI 双重问题）

`studio.png` 里「风格预设」下拉的内容是**音色名**（温柔女声 / 沉稳男声…），来自 `StudioModule._renderStyleOptions()` 直接映射 `API.getPresets()`。

但后端 `/api/generate/design` 的 `style` 参数语义是**风格描述**，会被 `combine_text(text, style)` 拼进 prompt 当成风格提示。也就是说：

> 用户选「沉稳男声」，后端收到的是把"沉稳男声"当成**风格词**拼到文本前面 —— 它既不是音色引用，也不一定是个合理的风格描述。

另外这个下拉**没有"无"选项**，用户无法不选风格。

**建议**（二选一）：
- **方案 1（推荐）**：把标签改成「音色参考」，并接上真正的克隆逻辑（对应后端 `voice_profile`）
- **方案 2**：换成真正的风格词表 —— 温柔 / 播报 / 激动 / 低沉 / 童声 / 无，与音色解耦

无论哪种，都要补一个「无」选项。

---

## F. 大屏下大面积留白

`library.png` / `studio.png` / `music.png` 里，内容只占顶部 30%–60%，下方是一整片空背景。1280×820 已经是最小窗口尺寸（`main.js` `minWidth:1024, minHeight:680`），实际用起来会更空。

**音色库最值得改**：现在是卡片网格，每张卡信息量只有「名称 + 12 字描述 + 一个标签 + 两个按钮」，密度太低。建议改成**列表视图**：

| 音色名 | 描述 | 声纹 | 试听 | 操作 |
|---|---|---|---|---|
| 温柔女声 | 温柔,清澈,语速中等 | 有声纹 | ▶ | 编辑 · 删除 |
| 沉稳男声 | 低沉,有磁性 | 有声纹 | ▶ | 编辑 · 删除 |

同样宽度能多放 3–4 倍信息，且天然解决下面 G、H 两条。

---

## G. 音色库不能试听 —— 而 API 早就支持了

`api.js` 里有 `getPresetVoiceUrl(name)` → `/api/preset/voice/{name}`，**全项目从未被调用过**。

音色库最核心的动作就是"听一下这个音色"，现在只能看到文字描述。建议在卡片/列表行加一个 ▶ 按钮，`new Audio(API.getPresetVoiceUrl(name)).play()` 即可，成本极低、收益很高。

---

## H. 卡片标题不截断，破坏网格对齐

`library.png` 第 4 张卡（名字很长）标题换行成两行，把卡片撑高、网格错位。

`.vlc-desc` 有 `text-overflow:ellipsis`，但 `.vlc-name` 没有。补上即可：

```css
.voice-library-card .vlc-name {
  overflow:hidden; text-overflow:ellipsis; white-space:nowrap;
}
```

---

## I. 禁用按钮不说明原因

- `studio.png`：「保存到音色库」灰着
- `music.png`：「生成音乐」灰着

用户第一反应是"坏了"还是"我漏了什么"，只能靠猜。

**建议**：加 `title="需先生成试听"`，或在按钮旁加一行 11px 的灰字说明当前禁用的原因。空状态永远比禁用状态更友好——更好的做法是按钮可点，点了提示"请先生成试听"。

---

## J. 「语气」标记条太小、语义不明

右下角那排 `语气: 笑 叹息 思考 疑问 嗯? 惊讶 不满 安静` —— 字号只有 11px、挤在文本卡底部，而且用户不知道点下去会发生什么（实际是往光标处插入 `[laughing]` 之类的标记）。

**建议**：
- 挪到文本框**上方**的工具条，与「字数」同一区域
- `title` 显示实际插入的标记，如 `title="插入 [laughing]"`
- 或收进一个「插入语气 ▾」下拉，日常不占视觉带宽

---

## K. 状态栏中间那串数字是重复信息

`状态栏` 居中显示 `20字 | 1次生成 | 0次下载`，但**文本框左下角已经有一个「20 字」**（`dub-char-count`）。

**建议**：状态栏只保留会话级统计（生成次数 / 下载次数），字数留在文本框旁边。或者干脆把状态栏右侧的 GPU 信息做得更有用——`GPU 8241M / 24576M` 这种原始 MB 数字，改成进度条 + `8.0G / 24G` 更易读，显存接近上限时变色警告。

---

## L. 只读/禁用状态、焦点态、无障碍

一批"打磨项"，单独看都小，合起来决定质感：

| 项 | 现状 | 建议 |
|---|---|---|
| 键盘焦点 | 只有 input 有 focus ring | 加 `:focus-visible { outline:2px solid var(--accent); outline-offset:2px }` |
| 导航按钮 | 只有 `title` | 补 `aria-label`、当前项加 `aria-current="page"` |
| 卡片可点区域 | 都是 `<div>` + click，键盘不可达 | 改 `<button>` 或加 `tabindex="0"` + Enter/Space 处理 |
| 动效偏好 | 未处理 | 加 `@media (prefers-reduced-motion: reduce) { * { animation:none!important; transition:none!important } }` |
| 音色卡选中态 | 只有边框变色 | 加左侧色条或 ✓ 角标，远看更明确 |

## M. 设计系统层面的两条建议

**1. 间距刻度不统一**

当前混用 2/4/6/8/10/12/16/18/20/24px。建议收敛到 4px 基准：**4 / 8 / 12 / 16 / 24 / 32**，用 token 表达（`--sp-1` … `--sp-6`）。卡片间 `margin-bottom:12px`、面板 `padding:16px`、卡片内 `padding:16px` 就会自然形成节奏。

**2. 图标重复内联**

麦克风 SVG 在 `index.html`、`dub.js`、`library.js` 里各写了一遍（5+ 次）。建议在 `index.html` 顶部放一个隐藏的 `<svg><symbol id="i-mic">…</symbol>…</svg>`，各处 `<use href="#i-mic">`。改一次图标全站生效，也顺带减小 HTML 体积。

## 优先级总表

| # | 事项 | 收益 | 改动量 |
|---|---|---|---|
| A | 波形重做（留白 + 间隙 + 中线 + 播放头） | ★★★ | 中（~40 行 canvas） |
| B | 播放器控制压成一行 + 内建音量 | ★★★ | 小（HTML + CSS） |
| G | 音色库加试听按钮 | ★★★ | **极小**（API 已就绪） |
| D | 表单最大宽度 + select 字重 + readonly 样式 | ★★☆ | 极小（纯 CSS） |
| H | 卡片标题省略号 | ★★☆ | 极小（1 条 CSS） |
| I | 禁用按钮给原因 | ★★☆ | 小 |
| C | 音量/语速/音调移到播放器旁 | ★★☆ | 中（涉及 DOM 搬移） |
| E | 「风格预设」语义修正 | ★★★ | 中（前后端约定） |
| F | 音色库改列表视图 | ★★☆ | 中 |
| J / K | 语气条位置、状态栏信息去重 | ★☆☆ | 小 |
| L / M | 焦点态、无障碍、间距 token、图标复用 | ★☆☆ | 中（面广但都是小改） |

**如果只做三件事**：A（波形）、G（试听）、B（控制栏）—— 这三项直接决定"这软件看起来专不专业"。
