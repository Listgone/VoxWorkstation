# 发布与本地验证流程

> 这份说明是为了固定两件事：**什么时候才升版本号**、**改动交付前怎么验证**。
> 之前版本号一天内从 1.6.0 涨到 1.6.3，用户侧看起来很像"天天更新"，实际只是小改动。

## 版本号规则

- **平时不动 `package.json` 的 `version`**。改功能只提交源码，不升版本号、不打安装包、不发 Release。
- **只在要交付时升一次**：`version` 对齐本次批次，然后构建安装包并发 Release。
- 批次内的小改动用提交说明记录，不占用版本号。
- 版本号要与"已发布的 Release"保持一致：
  - 当前源码里的 `version` = 最近一次已发布的版本号；
  - 已发布的 Release 与它相同（可以有一个"待发布"的提交区间，但不改版本号）。
- 交付后核对三处一致：`package.json`、GitHub Release、本机安装的 exe 版本。

## 交付前要跑的验证

在仓库根目录执行（都需要 Node / Electron 依赖已装好）：

```bash
# 语法
node --check main.js && node --check preload.js && node --check voices-backup.js

# 数据层与界面自检（脚本在仓库之外的工作区里）
node <工作区>/quick-workspace-selftest.js
node <工作区>/quick-merge-selftest.js
node <工作区>/quick-ui-selftest.js
node <工作区>/voices-backup-selftest.js
node <工作区>/voices-autobackup-selftest.js
```

涉及界面布局的改动，另跑离屏 Electron 探针截图确认（同样在工作区里）。

### 一键配置链路的验证（改动到这段时必须跑）

一键配置是最容易出问题的一步（历史上：pip 输出 GBK 编码崩溃、装成 CPU 版 torch、
模型下载半截）。它不依赖界面，可以直接在一次性目录里整链跑一遍：

```bash
node <工作区>/setup-e2e.js D:\setup-e2e                              # 完整链路（含下载依赖）
node <工作区>/setup-e2e.js D:\setup-e2e --skip-pip                   # 跳过装依赖，用系统 Python
```

脚本做的正是 `vox:setup:auto` 的同样步骤：从 `bootstrap/` 释放后端脚本 → 探测 Python →
用**完全相同的参数与环境变量**（`--index-url .../cu121` + `PYTHONUTF8=1`、
`PYTHONIOENCODING=utf-8`）安装依赖 → 写 `vox.config.json` → 启动后端并等 `/api/ready` →
真合成一句并校验返回是合法 WAV。

- 依赖装到一次性目录（`pip --target`），**不污染系统 Python**。
- 若已有模型，设 `VOX_E2E_REUSE_MODEL=<模型目录>` 复用它，省掉 4.6 GB 重复下载
  （走的是 `server.py` 的 `VOX_MODEL_DIR` 覆盖能力）。
- 想连"模型自动下载"一起测，就不设那个变量。

## 打包与发布

```bash
npm run build:win            # 必须走这个脚本：prebuild 会把 engine/server.py 同步进 bootstrap
```

- 安装包产物在 `dist/`，命名 `VoxWorkstation Setup <版本>.exe`。
- 发布用 `gh release create v<版本> <安装包> --notes-file <说明>`，说明采用统一格式：
  `新增 / 修改 / 删除 / 优化 / 修复 / 安装`，只写客观事实，不写对话语气与迭代过程。
- 静默安装必须带 `/D=` 指定目录，否则安装程序会直接退出（退出码 2）：
  `"VoxWorkstation Setup x.y.z.exe" /currentuser /S /D=D:\目标目录`

## 交付前必须确认的风险点

1. **`engine` 目录位置**：它是安装目录里的目录联接，真实数据在安装目录之外的兄弟目录
   （如 `D:\VoxStation\engine` → `D:\VoxWorkstation-engine`）。
   - 卸载/覆盖安装不会删掉真实数据（递归删除不跟随联接，已实测）。
   - 但**从 v1.6.1 及更早版本升级**时，执行的是旧版本自带的卸载器，仍会删除 engine；
     必须先暂存再安装。
2. **模型与音色是 4.6 GB + 用户资产**：任何"删除目录"的操作之前，先确认它不在真实数据路径上。
3. **音色备份**：手动备份为 `VoxVoices-…`，自动备份为 `VoxAuto-…`（默认节流 3 分钟、保留 20 份）。
   自动备份目录若用户未指定，会落在安装目录之外的 `VoxWorkstation-voices-backup`。
