# 霓虹紫夜（neonwave）设计语言

> 给谁看：后续设计界面、写 UI 插件、想加新主题的人。
> 为什么单写一份：这个主题的观感接近 iOS / ColorOS 这类现代系统界面，
> 而且在本项目里是**主推主题**。把它的规则写清楚，才能照着扩展而不是凭感觉调。
> 所有数值都来自 `renderer/css/style.css` 的 `[data-theme="neonwave"]` 变量块。

## 一句话

**深紫到蓝的渐变底 + 半透明白色"磨砂亚克力"面板 + 霓虹粉主色 + 青蓝状态色。**
关键不是"紫"，而是**面板靠半透明白叠出层次**，粉与青只用在**需要被看见的地方**。

## 一、层次：靠透明白的叠加，不靠阴影

| 层 | 值 | 用途 |
|---|---|---|
| 底 | `transparent`（真正铺底的是 `.neonwave-bg` 渐变层） | 应用背景 |
| 侧栏 | `rgba(26,10,55,.72)` | 深一档，把内容区衬出来 |
| 卡片 | `rgba(255,255,255,.14)` | 主面板 |
| 抬升 | `rgba(255,255,255,.10)` | 表头、区块头 |
| 悬停 | `rgba(255,255,255,.24)` | hover / 选中反馈 |
| 输入 | `rgba(255,255,255,.18)` | 输入框、下拉 |

**规则**：
- 层次用**透明白的 4 档**（.10 / .14 / .18 / .24）表达，**不要给每块加阴影**。
  阴影只留两级、且都很轻：`0 14px 44px rgba(20,6,48,.34)`、
  `0 26px 70px rgba(12,2,36,.46)`，只给弹窗与浮层。
- 相邻区块的透明度**至少差两档**（.10 vs .24），差 0.02（.10 vs .12）在深紫底上
  肉眼分不出来，会被看成一整块。**这是本项目踩过的坑。**
- 边框用白色低透明：常规 `rgba(255,255,255,.34)`、细分隔 `rgba(255,255,255,.20)`。
  边框是"描边"作用，不要用它来代替间距。

## 二、背景层：渐变 + 柔光晕，不要具象图案

- 底色：`linear-gradient(168deg,#180a34 0%,#2b1055 34%,#3b2a7d 66%,#4a5fae 100%)`
  —— 从深紫一路走到蓝，**第二个色标（34%）就转紫**，让上半屏偏紫、下半屏偏蓝。
- 之上叠一层压暗：`linear-gradient(180deg,rgba(8,3,26,.42),rgba(8,3,26,.10) 22%,…)`
  —— 顶部压暗保证标题栏可读。
- 光晕用 `<ellipse>` 径向渐变（品牌青 `#43f6ff`、粉 `#ff77e9`），**低透明度大字扩散**。
  本项目明确**去掉了太阳/网格这类复古具象图案** —— 具象图案在真实界面里会抢注意力。
- 背景层实现方式固定：`position:fixed;inset:0;z-index:0`，并且**淡入必须瞬时**
  （`transition:none`）。离屏/后台窗口里 CSS 过渡会长期停在中间值，淡入走过渡会卡在半透明。

## 三、配色：粉是"动作"，青是"状态"

| 角色 | 值 | 用在哪 |
|---|---|---|
| 主色 | `--accent:#ff77e9`（霓虹粉） | 主按钮、选中态、激活图标 |
| 主色 hover | `#ff9af0` | |
| 主色淡底 | `rgba(255,119,233,.22)` | 选中行、激活导航底色 |
| 主色上的文字 | `--accent-fg:#2b1055` | 粉底上的字**必须用深紫**，不能用白色（对比度不够） |
| 成功/状态 | `--ok:#43f6ff`（青） | 引擎就绪、完成态 |
| 警告 | `--warn:#ffd36e` | 加载中、需要注意 |
| 危险 | `--danger:#ff6b81` | 删除、失败 |
| 辅助紫 | `--purple:#b48cff` | 次要标记 |

**规则**：
- **一个屏幕里粉色是稀缺的**：只有主操作按钮、当前选中项、激活的导航图标用粉。
  不要给每个图标/标签都上粉，否则没有重点。
- **青蓝只表达状态**，不参与品牌识别 —— 这样"青=有情况，粉=可操作"能形成条件反射。
- 粉底上的文字一律深紫 `#2b1055`，颜色对比度是这个主题最容易被忽略的地方。
- 语义色都要配一个 `.18~.20` 的同色淡底（`--ok-soft` 等），用于胶囊标签。

## 四、文字三级

`--text:#ffffff`（正文/标题） → `--text-dim:#e6dcff`（次要，带一点紫调） →
`--text-mute:#c3b2ea`（最弱，说明文字）。
次要色**不是灰**，是**带紫调的白**，这是让整体保持"紫夜"气质的关键细节。

## 五、形状与字体

- 圆角四档：`--radius-sm:10px` / `--radius:12px` / `--radius-lg:18px` / `--radius-xl:26px`。
  卡片用 18，弹窗用 26，输入与按钮用 12，小控件用 10。**同一层不要混用不同档。**
- 标题字体：`"Trebuchet MS","Segoe UI","PingFang SC","Microsoft YaHei"`。
- 导航分组标题做**字距拉大 + 全大写**（`letter-spacing:.18em`），标题栏 logo
  `letter-spacing:.10em;text-transform:uppercase` —— 这类"松字距"是现代系统界面的共同特征。
- 强调元素允许轻微发光：`text-shadow:0 0 16px rgba(67,246,255,.35)`（如 KPI 数字）。
  **只给极少数数字用**，多了就廉价。

## 六、可直接照抄的几条

1. 面板 = 半透明白叠加，档位 .10 / .14 / .18 / .24，相邻至少差两档。
2. 背景 = 深紫→蓝渐变 + 顶部压暗 + 低透明光晕；不要具象图案。
3. 粉管动作、青管状态；粉底上的字用深紫。
4. 圆角按层级取固定档位，不随手写数值。
5. 标题与分组标签用增大字距体现"现代系统感"。
6. 背景层的淡入必须瞬时；过渡只用于淡出。

## 七、为什么它贴合 iOS / ColorOS 这类系统

把这套规则抽出来看，它命中了几条现代移动系统的共同手法：

- **半透明材质分层**（亚克力/毛玻璃）替代"卡片 + 阴影"的传统桌面范式；
- **大面积低饱和背景 + 小面积高饱和强调色**，强调色只落在可操作项上；
- **语义色与品牌色分工明确**（状态 vs 动作），不混用；
- **弱化边界线，靠明度差和间距分区**；
- **大圆角 + 松字距**的排印特征。

后续做新主题，只要保持这五条结构，换色即可成立；反之如果加了具象图案、
给每块都配阴影、把强调色铺满，就会立刻失去这种质感。
